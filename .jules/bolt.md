## 2024-08-02 - Isolate Modal State to Prevent Full-Page Re-renders
**Learning:** In the React application, keeping global modal state (`isArticleModalOpen`, etc.) at the very top level in `App.tsx` forces the entire app (including router components, header, footer, etc.) to re-render whenever a modal is toggled. Even though child components might be somewhat isolated, any state update in `App` cascades down unless everything is strictly memoized. Because modals are triggered via `window.postMessage` from deeply nested components (bypassing normal prop drilling), the modal state itself doesn't need to be in the main app tree.
**Action:** Extract modal management into its own isolated wrapper component (`<Modals />`) placed alongside (or just inside) the top-level providers, but outside the main view hierarchy. Use `React.memo` on this wrapper and `useCallback` on its handlers so that it only updates itself when modal states change, preventing expensive full-page re-renders.
