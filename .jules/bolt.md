## 2024-05-19 - Extracted Modals Component to Prevent Full-Page Re-renders
**Learning:** In the React application, keeping modal state (e.g., `isArticleModalOpen`) in the root `App.tsx` component causes the entire application to re-render whenever a modal is opened or closed. This is because state changes trigger a re-render of the component and all its children. This is especially problematic in an app that uses context providers (like `HelmetProvider` or custom contexts) or has many child components. Wrapping child components in `React.memo` isn't always enough if the parent passes down new object references or functions on every render.
**Action:** Extract the modal states and the modal components into a separate, memoized wrapper component (e.g., `<Modals />`). This isolates the state updates to the `<Modals />` component itself, preventing the root `App` and its main routing children from re-rendering when modals toggle. Since the modals are triggered via `window.postMessage`, the new `<Modals />` component can manage its own state independently without requiring props to be passed down from `App`.
